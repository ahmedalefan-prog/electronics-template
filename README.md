# فريق وكلاء بناء تطبيقات الإلكترونيات

فريق من 12 دوراً يعمل داخل Claude Code: منسّق + 11 وكيلاً متخصصاً، مصمَّم للعمل من الهاتف بالكامل.

## محتويات الحزمة

```
CLAUDE.md                      دليل المنسّق: المراحل، بوابات الجودة، قواعد العمل السحابي
.claude/agents/                الوكلاء الـ11
.github/workflows/ci.yml       بناء الـ firmware + اختبارات + محاكاة Wokwi + بناء التطبيق + فحص الأسرار
```

| الوكيل | المهمة |
|---|---|
| requirements-analyst | تحويل الفكرة إلى متطلبات قابلة للقياس |
| system-architect | المعمارية وقرارات التصميم |
| hardware-engineer | القطع، توزيع الأطراف، ميزانية الطاقة (مع مصدر لكل رقم) |
| firmware-engineer | كود المتحكم بـ PlatformIO + OTA + سجلات عن بعد |
| comms-engineer | بروتوكول الاتصال بين الجهاز والسحابة، وتحديث OTA |
| backend-developer | Supabase: الجداول، الصلاحيات، الدوال |
| frontend-developer | تطبيق Next.js PWA عربي |
| ux-designer | الشاشات والتنبيهات ومؤشرات الجهاز |
| test-engineer | الاختبارات والمحاكاة وتقرير التغطية |
| security-auditor | تدقيق أمني (لا يعدّل الكود) |
| code-reviewer | مراجعة الكود (لا يعدّل الكود) |

المنسّق هو جلسة Claude Code الرئيسية نفسها، ويقرأ تعليماته من `CLAUDE.md`.

## التركيب (من الهاتف)

1. على GitHub أنشئ مستودعاً جديداً، مثلاً `electronics-template`، وفعّل خيار **Template repository** من الإعدادات.
2. ارفع محتويات هذه الحزمة إليه كما هي، مع الحفاظ على المجلدات المخفية `.claude` و`.github`.
3. لكل مشروع جديد: **Use this template** ← مستودع جديد باسم المشروع.
4. افتح Claude Code من تطبيق Claude ← اختر المستودع ← اكتب طلبك.

## إعداد لمرة واحدة

- **محاكاة Wokwi في CI:** أنشئ رمزاً من موقع Wokwi (CI token)، ثم أضفه في المستودع: Settings ← Secrets ← Actions باسم `WOKWI_CLI_TOKEN`. بدونه تعمل بقية الخطوات وتُتخطّى المحاكاة.
- **Vercel:** اربط مجلد `app/` بمشروع Vercel لتحصل على رابط معاينة لكل PR.
- **Supabase:** مفاتيح المشروع توضع في متغيرات البيئة فقط، ولا تُكتب في الكود.

## طريقة الطلب

يوجد أمران جاهزان:
- `/new-project` متبوعاً بوصف المشروع: يبدأ مشروعاً جديداً بالفريق كاملاً.
- `/status`: يعرض حالة المشروع وبوابات الجودة في شاشة واحدة.

أو اكتب بالعربي ما تريده، وبأكبر قدر من التفاصيل التي تعرفها. مثال:

> أريد نظام مراقبة حرارة ورطوبة لمخزن، ثلاث نقاط قياس، تنبيه على الهاتف إذا تجاوزت الحرارة 30 درجة، الكهرباء تنقطع أحياناً، والواي فاي متوفر.

سيسألك المنسّق أسئلة قليلة، ثم يعرض عليك المعمارية للموافقة، ثم يبني ويختبر ويرسل لك رابط الـ PR ورابط المعاينة.

## نقاط توقّف المنسّق لسؤالك

1. بعد المتطلبات، إذا وُجدت أسئلة حاسمة.
2. بعد المعمارية واختيار القطع، وهذه موافقة إلزامية.
3. إذا بقيت مشكلة بعد 3 محاولات إصلاح.
4. قبل الدمج النهائي.

## أين ترى النتائج

- `docs/` المتطلبات والمعمارية والبروتوكول وتصميم الواجهة ودليل الرفع الأول
- `hardware/` قائمة القطع والتوصيلات
- `reports/` تقارير الاختبار والأمن والمراجعة وتغطية المتطلبات
- تبويب **Actions** في GitHub: نتيجة البناء والمحاكاة لكل تعديل
- تبويب **Pull requests**: كل التعديلات قبل دمجها

## تخصيص الفريق

كل وكيل ملف نصي في `.claude/agents/`، ويمكنك تعديل تعليماته مباشرة من GitHub على الهاتف. السطر `model:` يحدد النموذج: `opus` للتفكير العميق والمراجعة، و`sonnet` للبرمجة.
